# php_pdo_ords project context

- Project root: `/opt/php_ords`.
- Target design: native PHP PDO driver (`ords`) with a C Zend/PDO ABI shim and Rust HTTP/JSON backend; not a PHP class wrapper and no OCI/Instant Client dependency.
- Current development host: Ubuntu 22.04.5 LTS, ARM64 (`aarch64`), glibc; PHP CLI 8.1.34 (API `20210902`), 8.2.36 (`20220829`), 8.3.37 (`20230831`), 8.4.28 (`20240924`), 8.5.13 (`20250925`). Apache mod_php is 8.4.28; PHP-FPM 8.5 is enabled. PDO driver API is `20170320` for PHP 8.1–8.3 and `20240423` for 8.4–8.5.
- Toolchain on ARM host: Rust stable `1.100.0`, Cargo `1.100.0`, GCC/build-essential, matching PHP 8.4/8.5 development headers (PHP 8.1–8.3 headers unavailable), `gcc-x86-64-linux-gnu` and Rust x86_64 target for cross-builds.
- Rust dependencies pinned by Cargo.lock: `reqwest 0.12.28`, `serde 1.0.229`, `serde_json 1.0.154`, `zeroize 1.9.2`, `cc 1.11.3`.
- TLS: rustls certificate verification enabled by default. Plain HTTP is permitted only for loopback mock tests. Response body cap is 16 MiB. HTTP connect/request timeouts are bounded.
- ORDS endpoint: append `/_/sql` to the supplied REST-enabled schema endpoint. SQL uses `application/json` with `statementText`; constructor validates Basic Auth/OAuth2 credentials with `SELECT 1 FROM dual` and returns connection SQLSTATE `08001` on failure. PHP 8.4/8.5 ARM64 builds pass typed ORDS JSON `binds`, `offset` and `limit`; PHP 8.1–8.3 and x86_64 prebuilt artifacts are not yet rebuilt.
- ORDS REST-Enabled SQL is stateless by default: each HTTPS request maps to a new database session and successful statements auto-commit. PDO transaction callbacks reject calls with SQLSTATE `0A000`; no fake transaction state is exposed. ORDS sessionless transactions can provide a future transaction backend only when the target database/ORDS configuration supports it (Oracle Database 23ai Release 23.6+ documented support).
- PHP 8.4/8.5 ARM64 prepared statements send server-side typed JSON binds; ORDS still does not retain a prepared handle between independent HTTP requests. Persistent PDO connections are rejected.
- Binary compatibility: a `.so` must be built against the exact target PHP module API/headers. PHP 8.1–8.5 do not share one universal Zend ABI; build a separate artifact for every PHP API version and architecture.
- Built artifacts: ARM64 and cross-compiled x86_64 for all five PHP APIs `20210902`, `20220829`, `20230831`, `20240924`, `20250925`. ARM64 artifacts loaded and mock-integration-tested under PHP 8.1–8.5, including NULL, BOOLEAN, INTEGER, FLOAT, STRING, all common fetch modes, metadata, DML and error handling, `PDO::errorInfo()` and `PDOStatement::errorInfo()`. SELECT rowCount uses ORDS resultSet.count; pagination is available through `PDO_ORDS_ATTR_OFFSET` and `PDO_ORDS_ATTR_LIMIT`. PHP 8.4 Apache SAPI was tested via a temporary local script; PHP-FPM 8.5 config and reload verified. x86_64 artifacts are ELF-verified but cannot be runtime-loaded on this ARM host.
- OCI discovery from ARM host `eth0-114193` found Autonomous Database `Almakano-AI-01` (`ALMAKANOAI01`, `AVAILABLE`, Oracle Database 26ai, region `uk-london-1`). ORDS base URL: `https://g00a1d8fe471d43-almakanoai01.adb.uk-london-1.oraclecloudapps.com/ords`; DNS/TLS and unauthenticated ORDS response were verified. OCI reports `is-mtls-connection-required=true` for database connections. Live SQL is verified using REST-enabled schema alias `admin` and local `.env` credentials; `.env.example` and `tests/run-live-ords.sh` define the live-test profile without committing secrets. - ARM64 PHP matrix tests cover PDO registration, Basic Auth, emulated binds/quoting, prepare/execute/fetch, FETCH_ASSOC, FETCH_NUM, FETCH_BOTH, FETCH_OBJ, FETCH_COLUMN, metadata, exec, ORDS HTTP errors, timeout attribute and persistent-connection rejection.

- Advanced ORDS protocol implementation (2026-11-25): prepared PDO statements now send typed server-side JSON `binds` for named placeholders (`name`, without `:`) and positional placeholders (one-based `index`). `PDO_ORDS_ATTR_OFFSET` / `PDO_ORDS_ATTR_LIMIT` set request pagination (defaults 0 / 500). `PDO::PARAM_INPUT_OUTPUT` values are sent as ORDS `inout` binds and copied back from `items[0].binds[*].result`. `PDO::lastInsertId()` returns the first OUT/INOUT result; `lastInsertId($name)` matches the bind name. This is not sequence `CURRVAL` support because ORDS requests are stateless, nor a persistent prepared handle.
- Advanced feature validation: mock integration and real SQL passed against `Almakano-AI-01` (Oracle Database 26ai) on PHP 8.4 API `20240924` and PHP 8.5 API `20250925`: named and positional IN binds, pagination offset/limit, PL/SQL OUT and INOUT, lastInsertId name matching and persistence across read-only statements. Updated ARM64 artifacts are `dist/linux-aarch64/php-20240924/php_pdo_ords.so` and `dist/linux-aarch64/php-20250925/php_pdo_ords.so`; installed in matching PHP extension directories.
- Compatibility status: PHP 8.1–8.3 ARM64 artifacts and x86_64 artifacts were not rebuilt with the advanced feature code because matching development headers are unavailable on this ARM host. Existing binaries still pass the legacy integration matrix and retain emulated placeholders; do not advertise new JSON binds/pagination/OUT binds for those artifacts until rebuilt and runtime-tested.
